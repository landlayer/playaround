---

借用 XMonad 的“即时编译”，核心零污染；不是把 LIP 改造成解释器去“嵌入”到 Rust 或 C++ 窗口管理器里。而是直接用现在写好的 Go 编译器，让用户改了 config.lip 配置文件，wc在后台一秒钟把它编译成一个极轻量的 Go 进程常驻后台。让 Landlayer 只管通过 Unix Socket 发送键盘事件、执行几何命令。哪怕用户的 LIP 脚本写错了、崩溃了，也只是快捷键不响应，而不会整个桌面黑屏死锁。

而且可以让 LIP 的 Flow 机制会自动安排多核并行计算。不管你算十几个窗口的dx/dy几何距离有多复杂，LIP 自己在后台多核同时跑，算完后用 claim 确定性地把新坐标打包发给桌面渲染。

而 Wayland 里改变窗口大小是“异步”的，LIP 的 effect + perform 机制刚好适合干这个。改变窗口大小只算个“请求（effect）”，由底层的 Landlayer 核心（宿主）根据显卡的刷新节奏去统一放行（perform）。用语言底层的机制，天然消灭了窗口拉伸时的闪烁 Bug。
